# МТС — «Технологии, которые держат связь»

Лендинг с бесконечным зумом по восьми локациям (базовая станция → аэростат → исследовательский центр → дата-центр → офис → город → улица → квартира), финалом «Лидер технологий» и обычной страницей «Больше о МТС» + футер.

Стек тот же, что у референса thorgal.com, но без 3D:

| Слой | Что используется |
| --- | --- |
| Фреймворк | Astro 7, статическая сборка, Tailwind 4 |
| Скролл | Lenis: сцена идёт за прокруткой. На телефоне — свой степпер: тап или свайп → переход к следующей остановке |
| Графика | OGL (WebGL2): каждый слой — текстурированный квад, 2D-камера, дефокус через мипы, смаз, режимы наложения, premultiplied alpha |
| Анимации | GSAP (таймлайн заголовков и плашек, интро, переходы между остановками на телефоне) |
| Картинки | WebP, генерируются из исходников скриптом на sharp |

## Что где лежит

```
frontend/             фронт: Astro-проект целиком
  src/  public/       исходники и статика (готовые WebP — в public/img)
  scripts/            сборка картинок: build-images.mjs, bake-figma.py
  assets-src/         исходники картинок (в образ и на сервер не едут)
  Dockerfile          продакшен-образ: сборка Astro внутри образа → статика за nginx
  nginx.conf          отдача статики и кэширование
docker-compose.yml    продакшен: Traefik (80/443, Let's Encrypt) + фронт
.env.example          настройки деплоя: домен и почта для сертификата
deploy/deploy.sh      деплой на сервер
```

Пути вида `src/lib/…` и `scripts/…` ниже — внутри `frontend/`.

## Запуск

```bash
cd frontend
npm install
npm run images   # assets-src/**.png → public/img/*.webp (+ манифест)
npm run dev
npm run build && npm run preview
```

## Скролл и листание

Десктоп и планшет: сцену ведёт скролл (`src/lib/app.ts`). Секция сцены высотой около 31 экрана, её вьюпорт липкий, прогресс `t` — доля прокрутки секции. Чем дальше прокрутили, тем дальше ушли кадры; остановили прокрутку — кадр стоит. Сама сцена ничего не доигрывает: Lenis только сглаживает колесо и тачпад, после последнего события сцена доезжает около полсекунды.

- Длина прокрутки — по весам кадров (`VH_PER_UNIT` процентов высоты экрана на единицу веса): переход между локациями — от двух до трёх с половиной экранов.
- Кадр-заголовок держится экран с третью прокрутки (`TITLE_HOLD` в `timeline.ts`): камера стоит, заголовок на месте, а плашки появляются по одной через равные отрезки прокрутки (`holdAt`, раскладка — в `Experience.astro`). Прокрутка всё время что-то меняет на экране, и понятно, что листать нужно дальше. Удержание — растянутое окно внутри кадра, ключи сцен от него не зависят.
- За финалом вьюпорт открепляется, и сцена уезжает вверх вместе со страницей; дальше — «Больше о МТС» и футер.

Телефон (`src/lib/stepper.ts`): секция ровно в экран, страница под ней стоит, а тап или свайп запускает переход к следующей остановке, и он проигрывается сам.

- Остановки (`STOPS`): первый экран, по одной на каждую плашку (у квартиры плашек нет — на заголовок) и финал, всего 24.
- Чего нет в мобильном макете и как это сделано. У локаций 04–07 тексты в макете — заглушка (копия заголовка и плашки исследовательского центра): раскладка взята из макета, тексты десктопные. У локаций 05–07 в макете один кадр с одной плашкой: плашек у локации три, и на каждую свой шаг, как в 01–04. Между кадрами 121 и 122 (дата-центр → офис) перехода нет: он сделан как на десктопе — наезд в красное поле логотипа и выезд из красной грани куба. Кадров финала в мобильной секции нет — они десктопные.
- Жесты: тап и свайп; в узком окне на компьютере — колесо и тачпад (один жест на шаг), стрелки, PageUp/PageDown, пробел. Пока переход не разыгрался больше чем наполовину, новый жест не принимается.
- Жест колеса начинается с мелких дельт (тачпад — с 1–2 px), поэтому шаг даёт либо заметное событие (от 4 px), либо набранный путь (16 px). Остаток жеста и хвост инерции не считаются; новый жест — события после паузы или дельта, которая снова выросла.
- После последней остановки следующий жест отпускает страницу, и «Больше о МТС» с футером скроллятся как обычно; вернулись к самому верху — сцена снова берёт экран.

## Как устроена сцена

- `src/lib/timeline.ts` — таймлайн в «кадрах» раскадровки и выбор раскадровки (`VARIANT`). Каждый кадр имеет вес — долю пути по сцене (длины прокрутки, на телефоне — времени перехода); ключи любых треков задаются по кадрам и семплируются по прогрессу `t ∈ [0,1]`. Ключи пишутся в номерах кадров макета: у десктопных сцен через `D()` (`D(18)` — кадр «18» секции Desktop), у мобильных через `M()` (`M(127)` — кадр «127» мобильной секции). Десктоп: кадры 0…44 = кадры макета 01…45, дальше 45…47 — финал. Мобильный: 54 кадра — кадры макета 92…134, где кадры-заголовки 122, 127 и 131 занимают по три кадра таймлайна (по одному на плашку), за 121 идут два кадра перехода в офис, а за 134 — три кадра финала.
- `src/lib/scenes.ts` — описание локаций: слои, треки камеры, альфа, затемнение, размытие. Координаты — в системе фрейма сцены (1920×1080, у мобильных сцен `ref: 393×645` — кадр без статус-бара и панели браузера).
  - `space: 'scene'` — слой живёт в пространстве локации, камера его зумит.
  - `space: 'screen'` — слой задан в координатах экрана (как узел в кадре Figma) и не зависит от камеры. Так ведём аэростат, который перелетает между локациями, планы с собственным масштабом (крыша и город в 01) и все мобильные слои.
  - `depth` — параллакс (0 фон, 1 ближний план, отрицательный — «за окном», облака).
  - `blur` — размытие в px макета, как layer blur в Figma; `alpha`, `rotate`.
  - `blend` — `screen` (облака на дневном небе) или `add` (свет, plus-lighter в Figma); `lit` — слой не темнеет вместе со сценой.
  - `dof` — глубина резкости: эллипс в пространстве слоя, внутри которого слой резкий, а за ним плавно размывается (техник в дата-центре при наезде на логотип).
  - `paint` — процедурная текстура вместо картинки: градиент неба, свечение солнца. Рисуется на канвасе при загрузке.
  - `drift`, `cloud` — движение облаков, см. ниже.
- `src/lib/webgl/Stage.ts` — рендер. Один шейдер, один квад, `mesh.draw()` на слой. Размытие и сильное увеличение слоя идут через бикубическую выборку (B-сплайн) с уменьшенных копий текстуры — мипов. Выборка берётся строго по сетке целого уровня, промежуточная сила размытия — смесь двух соседних; на «дробном уровне» сетка весов расходится с текселями, и размытие идёт ступеньками. Мипы со второго уровня Stage строит сам, с ядром [1 3 3 1], вместо усреднения 2×2 от видеокарты: на диагональных линиях оно даёт зубцы. Текстуры заливаются в видеопамять заранее (`warm()`), пока сцена стоит, — первое появление слоя не даёт рывка.
- `src/lib/stepper.ts` — листание на телефоне: жесты, остановки, переходы между ними.
- `src/lib/overlay.ts` — DOM поверх WebGL: заголовки, плашки с выносками, волны у антенны, подсказка первого экрана, логотип и слоган финала (логотип летит из шапки на своё место в связке; откуда и куда — меряется по вёрстке). Позиции в координатах макета, вписанного в экран по cover — те же, что у screen-слоёв. В мобильной раскадровке на каждую плашку свой кадр, а её выноска считается на лету до точки сцены.
- `src/lib/bokeh.ts` — свет исследовательского центра и дата-центра (2D-канвас): лампы, которые светятся в зале, остаются гореть, когда он гаснет, и растворяются в темноте до появления дата-центра; красное боке у стойки. Канвас смешивается со сценой сложением (`plus-lighter`, как в макете): на светлом зале огни светятся, а не лежат тёмными пятнами. Точки привязаны к пространству своих локаций и едут вместе с камерой.
- `src/lib/content.ts` — тексты и раскладка плашек. Переносы строк (`\n`) в заголовках, абзацах и плашках повторяют макет: на десктопе строки не переносятся (`white-space: nowrap`), на мобильных текст течёт сам. Выноска плашки — сторона, точка выхода, длина и поворот (`side`, `at`, `len`, `turn`).

Ключи камеры сняты с геометрии фонов в кадрах Figma по формуле `cam = (tx − bx/s, ty − by/s, 1920/s, 1080/s)`, где `(bx, by, bw)` — узел фона в кадре, `(tx, ty, tw)` — он же в кадре-заголовке, `s = bw / tw`.

### Плавность переходов

Одна картинка нигде не растворяется в другой: локация сменяется в тот момент, когда на экране нет ничего, кроме ровного цвета или вида, общего для обеих.

| Переход | Как сменяется картинка |
| --- | --- |
| 01 → 02 | камера поднимается в небо; когда город ушёл под кадр, небо одной локации долго переходит в небо другой и заканчивает к тому моменту, когда снизу показалось поле |
| 02 → 03 | наезд внутрь корпуса аэростата: белая обшивка закрывает экран, её сменяет обшивка модели, отъезд открывает лабораторию |
| 03 → 04 | свет гаснет до черноты, остаются лампы; в темноте они расплываются и тают, а на их месте загораются огни стоек; зал дата-центра проступает из темноты, когда его огни уже горят |
| 04 → 05 | наезд на логотип на куртке с глубиной резкости: техник в фокусе, зал за ним уходит из фокуса; дальше — в красное поле логотипа: экран целиком красный, отъезд идёт уже из красной грани куба в офисе |
| 05 → 06 | камера проходит сквозь стекло: офис уходит за края кадра, город за окном дорастает до полного кадра |
| 06 → 07 | поворот: перед камерой проходит фасад дома — не в фокусе, как близкий предмет (его картинка 941 px шириной растянута в 3.6 раза, без заметного размытия она выглядела бы пиксельной) |
| 07 → 08 | камера стартует внутри проёма окна квартиры и отъезжает: рама входит в кадр с краёв, улица остаётся видом из окна |
| 08 → финал | комната и улица гаснут, логотип из шапки вырастает в центр кадра |

Что стоит за этим в коде:

- Треки — монотонные кубические сплайны (Фритч — Карлсон): камера проходит промежуточные ключи без остановок и не перелетает за значения ключей.
- Зум идёт в логарифме размера, а центр кадра следует за размером, а не за временем (`sampleRect`). Наезд между двумя ключами — масштабирование вокруг неподвижной точки: цель не «плывёт» вбок, пока камера приближается.
- Промежуточные кадры макета не всегда согласованы между собой (объект переставлен без связи с соседними кадрами), поэтому наезды заданы опорными кадрами, а путь между ними камера проходит сама. Где это сделано, отмечено в комментариях `scenes.ts`.
- Наезд «сквозь предмет» идёт дальше, чем нужно, чтобы предмет закрыл экран: его края покидают кадр на ходу, а торможение приходится на невидимый остаток пути. Там, где камера уходит на десятки крат, кадрам перехода дано больше времени (`SLOW_FRAMES` в `timeline.ts`).
- Расфокус офиса на пути к окну тоже идёт по зуму камеры (`officeDefocus`): картинка там растянута в разы, и со слабым размытием она выглядит не «не в фокусе», а нерезкой, из крупных пикселей. Резкость уходит с офиса сразу, как камера трогается, и остаётся на городе.
- Город за окном офиса привязан не ко времени, а к зуму камеры (`cityThroughWindow`): растёт медленнее рамы, как дальний план, и встаёт на место к тому моменту, когда стекло закрывает экран. Кривая подобрана по маске стекла — при каждом зуме город закрывает всё стекло, которое есть в кадре.
- Улица за окном квартиры так же идёт за камерой квартиры (`streetBehindWindow`). У её планов есть края, а вид из окна шире картинки, поэтому улица начинает отъезжать только тогда, когда оба откоса окна вошли в кадр: края всё время остаются за стеной.
- Слой с ключами в разных пространствах (аэростат, город) на участках без привязки идёт общим сплайном и не останавливается на каждом ключе (`plainRun` в `Stage.ts`).
- Слой, который быстро едет через экран, получает короткий смаз вдоль движения. Куда и как быстро он едет, берётся из треков (место слоя при `t` и чуть дальше), а темп прокрутки сглажен: толчки колеса мыши не заставляют смаз мигать. Меряется ход того, что сейчас в середине экрана, за вычетом расхождения точек при наезде, — смаз остаётся только панорамам (проезд фасада, поворот к улице).
- Если кадры не успевают, канвас понижает плотность пикселей (`app.ts`).

Проверка на просвет фона: сцена рисуется дважды с разным цветом очистки, и любая разница между кадрами — место, где сквозь слои виден фон. Так проверен весь таймлайн на десктопе и телефоне. Остаются два места, где фон виден слабее чем на 7%: мягкие края исходника офиса в его кадре-заголовке (в макете так же) и отдельные полупрозрачные пиксели внутри фасада.

### Видео на экранах и живые детали

План анимаций от дизайнера — `МТС.pdf` (9 слайдов, по локациям; в репозиторий не входит). Что из него сделано и на чём держится:

- **Видео на экранах** (`video`, `quad` у слоя; файлы в `frontend/public/video`, исходники — `assets-src/video`). В картинке экран вырезан в прозрачность, под неё кладутся тёмная подложка и видео с тем же прямоугольником; углы экрана заданы в px картинки (`uvQuad`), шейдер натягивает кадр на четырёхугольник в перспективе. Видео играет только пока слой в кадре, без звука; загрузчик его не ждёт. Сейчас: ноутбук техника на крыше (01), два ноутбука и монитор в офисе (05). Ролики для исследовательского центра лежат в `assets-src/video` и ждут вырезанных экранов.
- **Ветер** (`sway`): низ спрайта стоит, верх ходит из стороны в сторону. Дерево, кусты и цветы на поле (02) — отдельные спрайты, вырезанные из того же листа, что плита поля (`bake-figma.py v6`); `attach` привязывает их к плите, чтобы от мыши они сдвигались вместе с ней.
- **Машина** на поле подъезжает к своему месту и тормозит, пока камера приходит к заголовку (трек привязан к прокрутке).
- **Линии связи** от аэростата к домам — SVG в оверлее (`#links`), штрихи бегут вниз; стоят в пространстве локации 02 и едут с её камерой.
- **Аэростат** покачивается (`bob`) и слегка идёт за мышью (`hover`).
- **Огни стоек** в дата-центре мигают (`twinkle`): слой поделён на ячейки, большая часть из них гаснет и загорается в своём ритме; границы ячеек мягкие, а на размытом слое мигание сходит на нет. Красное боке у ближней стойки переливается (`bokeh.ts`).
- **Потоки воздуха** из вентиляторов на крыше (`haze`): в зоне над решёткой картинка слегка дрожит — и сама решётка, и город за струёй.
- **Смена света в офисе** (`pulse`): две картинки одного кадра, без солнца и с солнечными пятнами, совмещены точка в точку; вторая плавно проступает и уходит раз в 13 секунд.
- **Город** собран из слоёв, как в макете: градиент неба, солнце, четыре слоя облаков и город с вырезанным небом. Все идут одним треком (`inCity`), облака плывут вместе с прокруткой.
- **Улица**: дым над трубами завода и мерцающие фонари — рисуются на канвасе огней (`bokeh.ts`), пока улица стоит во весь кадр.
- **Исследовательский центр**: часть трековых спотов заметно мерцает (`bokeh.ts`).
- **Часы** на колонке в квартире (`#clock` в оверлее): поверх куска картинки без нарисованных цифр (`public/clock-face.png`, `bake-figma.py`) идёт своё время, минута раз в 10 секунд.

### Облака

Облака — отдельные слои во всех трёх сценах с небом: три в 01, пять в 02, семь в 07. Небо под ними — процедурный градиент, поэтому облака двигаются независимо от него:

- `drift` — облако плывёт вправо вместе с прокруткой: на сколько px макета оно смещается за кадр раскадровки (у каждого своя скорость: ближние и крупные быстрее). Движение привязано к скроллу, а не ко времени: на кадре-заголовке (`driftFrom` у сцены) облака стоят на местах из макета, на подлёте и отлёте заметно едут. Дошло до края кадра — то же облако выходит с другой стороны, перенос за кадром.
- `cloud` — «дыхание»: шум в шейдере смещает выборку текстуры на несколько px, края облака медленно перетекают.
- Отрицательный `depth` — параллакс от мыши и при зуме, как у далёкого плана.

Дневные облака смешиваются в режиме screen, как в макете. Закатные в макете лежат в режиме soft-light — в WebGL слой не видит того, что под ним, поэтому смешивание с небом запечено в спрайты (`bake-figma.py`). При `prefers-reduced-motion` облака стоят, смаза нет.

## Картинки

`npm run images` жмёт исходники из `assets-src/` в WebP по карте `MAP` в `scripts/build-images.mjs` и удаляет из `public/img` файлы слоёв, которых в карте больше нет.

Слои лежат в `assets-src/v3/` (локации 01–03, десктоп и мобильная раскадровка), `assets-src/v4/` (финальный макет: облака и локации 04–08) и `assets-src/v5/` (мобильная раскадровка локаций 04–08: вертикальные исходники идут как есть — в макете у них нет ни цветокоррекции, ни кропа; свет дата-центра отдельным слоем готовит `bake-figma.py v5`). Часть из них готовит `python3 scripts/bake-figma.py [v3] [v4]` (нужны numpy и Pillow) из выгрузок Figma в `raw/`. Отдельный шаг нужен потому, что MCP отдаёт три вида картинок и ни один не годится как есть:

- исходник заливки — полный размер и альфа, но без цветокоррекции и кропа, заданных в Figma;
- заливка из `get_design_context` — с цветокоррекцией и кропом, но ужатая до 1024 px (заливки без коррекции приходят в полном размере);
- рендер узла — точный цвет, но прозрачность залита фоном, а узел обрезан кадром.

Поэтому для вырезок (крыша, дальний план, аэростат, модель, дом и дальний план улицы, фасад) цветокоррекция снимается с пары «исходник → эталон» и переносится на полный исходник, а непрозрачные фоны (лаборатория, город) берутся рендером узла. Аэростат в макете растянут и скошен (`rotate 8° · scaleY 0.99 · skewX 8°`) — это запекается в текстуру, в сцене он обычный прямоугольник.

Что скрипт делает для финального макета:

- облака 01 — три окна одного листа, 02 — пять узлов: вырезаются по содержимому, прямоугольник спрайта в кадре печатается в консоль (его и вписывают в `scenes.ts`);
- облака 07 — то же плюс запекание soft-light по небу кадра 41;
- у облака, срезанного краем листа, альфа плавно сводится в ноль — иначе при дрейфе срез въезжал бы в кадр ровной вертикалью;
- стойка у края дата-центра — из рендера узла, альфа восстановлена по левой кромке.

Небо всех трёх сцен и оба «светила» в сборку картинками не идут — это градиенты из `scenes.ts`.

## Слои от иллюстратора

Требования те же, что в `материалы-для-локаций.md`: фон отдельным слоем с дорисовкой за объектами, объекты — вырезанные с альфой, исходники 3500–4000 px, пары «широкий/крупный план» с одного ракурса.

Чтобы добавить слой:

1. Положить PNG в `assets-src/`, добавить строку в `MAP` в `scripts/build-images.mjs`, выполнить `npm run images`.
2. В `src/lib/scenes.ts` добавить `{ id, img, space, rect, depth, blur }` в нужную локацию. Для объектов из PSD/Figma достаточно взять координаты узла в кадре-заголовке.
3. Если объект должен «переезжать» между локациями — задать `rect` как список ключей по кадрам.

## Шрифты

В макете MTS Wide (Medium, Bold) и MTS Text (Regular). Лежат в `public/fonts/` как WOFF2 (сконвертированы из TTF через fontTools), подключены в `src/styles/global.css` и предзагружаются в `src/layouts/Base.astro`. MTS Text Medium не передавался — Regular закрывает веса 400–500.

## Что сделано кодом, а не графикой

Небо и солнце (градиенты), движение облаков, волны вокруг антенны, лампы лаборатории и боке дата-центра, плашки и выноски, затемнения, дефокус и смаз, зерно, финальная связка логотипа со слоганом.

## Деплой (scroll.testforspec.ru)

Продакшен — `docker-compose.yml` в корне: Traefik принимает 80 и 443, переводит HTTP на HTTPS, сам выпускает и продлевает сертификат Let's Encrypt (проверка TLS-ALPN, хранится в томе `letsencrypt`) и отдаёт фронт — статическую сборку Astro за nginx.

```bash
./deploy/deploy.sh                      # сервер по умолчанию — root@178.250.159.72, каталог /opt/mts-scroll
HOST=user@host REMOTE_DIR=/path ./deploy/deploy.sh
```

Скрипт отправляет исходники на сервер (без `node_modules`, `dist`, `assets-src` и `.git`) и собирает образ там: `docker compose build --no-cache --pull` — без кеша слоёв, со свежими базовыми образами, зависимости ставятся из `package-lock.json` через `npm ci`. Локальная сборка в деплое не участвует. Потом `docker compose up -d`.

На сервере нужны Docker с плагином compose, вход по SSH-ключу и файл `.env` в каталоге проекта (образец — `.env.example`): `DOMAIN` — домен, A-запись которого указывает на сервер; `ACME_EMAIL` — почта для Let's Encrypt, можно оставить пустой.

Кэширование (`frontend/nginx.conf`): файлы `/_astro/` с хэшем в имени кэшируются навсегда, шрифты — на месяц. Картинки слоёв лежат под постоянными именами и меняются от деплоя к деплою, поэтому браузер перед использованием сверяется с сервером (`no-cache`, ответ 304, если файл тот же): после деплоя никто не увидит новую сцену со старыми слоями.

### Сервер 178.250.159.72

На сервере стоит панель ISPmanager со своим nginx. Чтобы отдать порты 80 и 443 Traefik, блок по умолчанию в `/etc/nginx/nginx.conf` (заглушка, phpMyAdmin, веб-почта) переведён с публичного 80 на `127.0.0.1:8880`; прежний конфиг лежит рядом — `nginx.conf.bak-before-traefik-2026-10-06`. Панель (`:1500`, `:1501`), почта, FTP и база работают как раньше. Сайты, созданные через панель, на 80/443 работать не будут, пока эти порты у Traefik; если панель перезапишет `nginx.conf` и вернёт `listen 80`, после перезагрузки сервера nginx и Traefik будут спорить за порт.

```bash
ssh root@178.250.159.72
cd /opt/mts-scroll
docker compose ps
docker compose logs -f traefik
```
